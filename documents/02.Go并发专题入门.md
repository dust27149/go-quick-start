# Go 并发专题入门

这份文档专门讲 Go 并发开发里最常见的几块内容：
- goroutine
- channel
- select
- WaitGroup
- 超时控制
- 并发任务模式

内容按“概念 -> 基础模式 -> 实战模式”的顺序展开。

版本基准：本文档以 Go 1.26.5 为基准进行介绍。

## 1. goroutine 是什么

### 定义

goroutine 是 Go 提供的轻量级并发执行单元。

### 最小示例

```go
go func() {
	println("hello from goroutine") // 在新的 goroutine 中执行
}()
```

或者：

```go
func work() {
	println("working") // 普通函数本体
}

func main() {
	go work() // 把 work 放到新的 goroutine 中执行
}
```

`go` 关键字用于把函数放到新的 goroutine 中执行。

### 工程注意点

- 主 goroutine 结束时，整个进程会退出。
- 需要结果或完成信号时，必须显式等待（channel 或 WaitGroup）。

### 常见坑

错误示例：

```go
package main

func main() {
	go func() {
		println("可能来不及打印")
	}()
}
```

上面程序可能没有输出，因为 `main` 已经结束。

## 2. channel 是什么

### 定义

channel 是 goroutine 之间传递数据和同步事件的通道。

### 最小示例

创建一个整型通道：

```go
ch := make(chan int)
```

发送数据：

```go
ch <- 10 // 发送一个整数到 channel
```

接收数据：

```go
value := <-ch // 从 channel 接收一个值
```

### 可运行示例

```go
package main

import "fmt"

func main() {
	ch := make(chan int) // 创建 channel

	go func() {
		ch <- 42 // 子 goroutine 发送结果
	}()

	v := <-ch // 主 goroutine 接收结果
	fmt.Println(v) // 打印结果
}
```

程序流程：

1. 主 goroutine 创建 `ch`
2. 启动子 goroutine
3. 子 goroutine 向 `ch` 发送 `42`
4. 主 goroutine 从 `ch` 接收值
5. 打印结果

### 工程注意点

- 无缓冲 channel 发送和接收必须配对，带同步语义。
- 带缓冲 channel 适合短时削峰，但不能替代限流和背压设计。

### 常见坑

- 发送/接收次数不匹配会导致阻塞。
- 不应该由接收方随意关闭仍在发送的 channel。

## 3. 无缓冲 channel

默认情况下，`make(chan T)` 创建的是无缓冲通道。

```go
ch := make(chan int)
```

无缓冲通道的特点：

- 发送会阻塞，直到有人接收
- 接收会阻塞，直到有人发送
- 很适合做同步协作

示例：

```go
package main

import "fmt"

func main() {
	ch := make(chan string)

	go func() {
		fmt.Println("发送前")
		ch <- "hello" // 无缓冲：这里会阻塞到接收方就绪
		fmt.Println("发送后")
	}()

	msg := <-ch // 接收后，发送方才会继续执行
	fmt.Println("收到:", msg)
}
```

## 4. 带缓冲 channel

如果你不希望发送操作立刻阻塞，可以用带缓冲 channel。

```go
ch := make(chan int, 3)
```

这表示这个通道最多缓存 3 个元素。

示例：

```go
package main

import "fmt"

func main() {
	ch := make(chan int, 2) // 容量为 2 的缓冲 channel

	ch <- 1 // 先写入两个元素
	ch <- 2

	fmt.Println(<-ch) // 再依次读出
	fmt.Println(<-ch)
}
```

适用场景：

- 任务生产速度快于消费速度
- 想减少发送方的即时阻塞
- 想实现简单的任务队列缓冲

## 5. 用 channel 发送结果

```go
package main

import "fmt"

func sum(a, b int, ch chan int) {
	ch <- a + b // 把计算结果发送给接收方
}

func main() {
	ch := make(chan int) // 用 channel 接收异步结果
	go sum(3, 5, ch) // 启动异步计算
	result := <-ch // 等待结果返回
	fmt.Println("结果:", result)
}
```

这是最基础的“异步计算 + 结果回传”模式。

## 6. 用空结构体做完成通知

如果你不需要传业务数据，只需要通知“做完了”，可以用 `chan struct{}`。

```go
done := make(chan struct{})

go func() {
	// 执行任务
	done <- struct{}{} // 任务完成后发送一个空结构体通知主 goroutine
}()

<-done // 等待任务完成
```

优点：

- 语义清晰
- 不传无用数据
- 很适合一次性完成通知

## 7. close 和 range

当发送方明确知道不会再发送数据时，可以关闭 channel。

```go
close(ch)
```

接收方可以用 `range` 读取直到通道关闭：

```go
package main

import "fmt"

func main() {
	ch := make(chan int) // 发送方会在结束前关闭通道

	go func() {
		for i := 1; i <= 3; i++ {
			ch <- i // 依次发送数据
		}
		close(ch) // 发送完毕后关闭通道
	}()

	for v := range ch { // 一直读取，直到通道关闭且数据读完
		fmt.Println(v)
	}
}
```

注意：

- `for v := range ch` 会持续读取，直到“通道已关闭且数据已读完”才退出。
- 通道未关闭时，如果当前没有可读数据，`range` 会阻塞等待。
- 对带缓冲 channel，关闭后会先把缓冲区剩余数据读完，再退出循环。
- 对无缓冲 channel，发送和接收需要实时配对；如果没有发送方，`range` 会阻塞。
- 一般由发送方关闭 channel。如果接收方使用 `range` 等待结束，发送方通常需要在发送完成后 `close(ch)`。
- 已关闭的 channel 不能再次关闭，因此不要在多个发送方中随意 `close(ch)`，否则容易触发重复关闭 panic。
- 向已关闭的 channel 发送数据会 panic

## 8. select

`select` 用于同时等待多个 channel 操作。

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	ch1 := make(chan string)
	ch2 := make(chan string)

	go func() {
		time.Sleep(1 * time.Second)
		ch1 <- "task 1"
	}()

	go func() {
		time.Sleep(2 * time.Second)
		ch2 <- "task 2"
	}()

	select {
	case msg := <-ch1:
		fmt.Println("收到:", msg)
	case msg := <-ch2:
		fmt.Println("收到:", msg)
	}
}
```

这里会优先打印更早完成的结果。

### default 分支

有 `default` 时，`select` 的规则是：

- 如果有可立即执行的 case（收/发已就绪），执行其中一个 case
- 只有当所有 case 都暂时不能执行时，才执行 default。

因此当有 `default` 时，`select` 不会阻塞。

```go
ch := make(chan int, 1)
ch <- 10 // 若注释这一行，select 没有可立即执行的 case，会走 default 分支

select {
case v := <-ch:
	fmt.Println("case:", v)
default:
	fmt.Println("default")
}
```

## 9. 超时控制

并发任务经常需要超时保护。

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	ch := make(chan string)

	go func() {
		time.Sleep(3 * time.Second)
		ch <- "完成"
	}()

	select {
	case msg := <-ch:
		fmt.Println(msg)
	case <-time.After(1 * time.Second):
		fmt.Println("超时")
	}
}
```

常见场景：

- 网络请求超时
- 后台任务超时
- 外部依赖等待超时

## 10. sync.WaitGroup

### 定义

如果只需要等待一组 goroutine 结束，`sync.WaitGroup` 更直接。

### 最小示例

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup // 用来等待 3 个 worker 完成

	for i := 1; i <= 3; i++ {
		wg.Add(1) // 每启动一个 goroutine，计数加 1

		go func(n int) {
			defer wg.Done() // goroutine 结束时计数减 1
			fmt.Println("任务", n) // 打印当前任务编号
		}(i)
	}

	wg.Wait() // 等待直到计数归零，表示所有 goroutine 完成
	fmt.Println("全部完成")
}
```

### 工程注意点

- `wg.Add(1)` 表示新增一个待完成任务
- `defer wg.Done()` 表示当前任务结束时减一
- `wg.Done()` 可以在 goroutine 内部调用，并用 `defer` 修饰，确保即使发生 panic 也能正确计数；执行次数需与 `wg.Add()` 的执行总和一致
- `wg.Wait()` 阻塞直到计数归零

### 常见坑

- `Add` / `Done` 数量不一致会导致永久等待或 panic。
- 不要在 goroutine 内部临时补 `Add`，应在启动前确定任务数。

### channel 和 WaitGroup 怎么选

- 需要传递结果或信号时，用 channel
- 只需要等待一组任务结束时，用 WaitGroup
- 两者可以组合使用

## 11. worker pool 模式

这是 Go 并发里的常见模式：

- 一个任务队列
- 多个 worker goroutine
- 每个 worker 从通道取任务并处理

示例：

```go
package main

import (
	"fmt"
	"sync"
)

func worker(id int, jobs <-chan int, wg *sync.WaitGroup) {
	defer wg.Done() // worker 完成时调用 Done
	for job := range jobs { // 持续从通道里取数据，直到通道关闭且数据被读完
		fmt.Printf("worker %d 处理任务 %d\n", id, job)
	}
}

func main() {
	jobs := make(chan int, 5) // 创建一个带缓冲的任务通道
	var wg sync.WaitGroup // 声明 WaitGroup

	for i := 1; i <= 3; i++ {
		wg.Add(1) // 每启动一个 worker，计数加 1
		go worker(i, jobs, &wg) // 启动 worker goroutine
	}

	for job := 1; job <= 5; job++ {
		jobs <- job // 发送任务到 jobs 通道
	}
	close(jobs) // 关闭 jobs 通道，通知 worker 没有更多任务

	wg.Wait() // 等待所有 worker 完成
}
```

适用场景：

- 批量处理文件
- 批量请求外部接口
- 批量消费消息

上面这种 worker pool 主要解决“任务怎么分给多个 worker 去做”的问题。若还需要把多个 worker 的结果统一收回来，就可以继续用扇出 / 扇入模式。

## 12. 扇出 / 扇入模式

### 扇出

把一个任务源分发给多个 worker 并发执行。

### 扇入

把多个 worker 的结果汇总回一个结果通道。

### 优点

- 能把同类任务并行处理，提升整体吞吐量。
- 任务分发和结果汇总分离，结构清晰，便于维护。
- worker 数量可以按负载调整，扩展性好。
- 结果统一汇总后，便于排序、去重、统计和错误处理。

### 适用场景

- 批量处理文件、消息或接口请求。
- 单个任务彼此独立，适合并发执行。
- 需要把多个结果集中汇总后再继续处理。
- 希望通过固定 worker 数量控制并发规模。

简化示例：

```go
package main

import "fmt"

func worker(id int, input <-chan int, output chan<- string) {
	for n := range input {
		output <- fmt.Sprintf("worker %d -> %d", id, n*n) // 把结果写到输出通道
	}
}

func main() {
	input := make(chan int) // 输入通道
	output := make(chan string) // 输出通道

	for i := 1; i <= 2; i++ {
		go worker(i, input, output) // 启动两个 worker
	}

	go func() {
		for i := 1; i <= 4; i++ {
			input <- i // 发送任务到输入通道
		}
		close(input) // 发送完成后关闭输入通道
	}()

	for i := 0; i < 4; i++ {
		fmt.Println(<-output) // 读取每个 worker 的结果
	}
}
```

## 13. 竞态和共享数据

Go 并发里一个常见风险是多个 goroutine 同时读写共享变量。

错误示例：

```go
var count int

go func() {
	count++ // 多个 goroutine 同时修改共享变量，可能产生竞态
}()

go func() {
	count++ // 同上
}()
```

这可能产生竞态条件。

解决思路：

- 尽量通过 channel 传递数据，减少共享状态
- 必须共享时，用 `sync.Mutex`
- 用 `go test -race` 检查竞态

## 14. 典型实战模式：并发请求多个接口

### 定义

并发请求多个接口是 goroutine + channel 的高频实战模式。

### 最小示例

```go
package main

import (
	"fmt"
	"net/http"
	"time"
)

func fetch(url string, ch chan<- string) {
	client := http.Client{Timeout: 3 * time.Second} // 每个请求设置超时
	resp, err := client.Get(url) // 发起请求
	if err != nil {
		ch <- fmt.Sprintf("%s -> error: %v", url, err) // 把错误回传给主 goroutine
		return
	}
	defer resp.Body.Close() // 关闭响应体

	ch <- fmt.Sprintf("%s -> %d", url, resp.StatusCode) // 回传状态码
}

func main() {
	urls := []string{"https://example.com", "https://golang.org"} // 需要并发请求的 URL 列表
	resultCh := make(chan string) // 汇总结果的通道

	for _, url := range urls {
		go fetch(url, resultCh) // 每个 URL 启动一个 goroutine
	}

	for range urls {
		fmt.Println(<-resultCh) // 依次收集结果
	}
}
```

### 工程注意点

- 每个请求都应设置超时，避免单点卡死。
- 结果通道的接收次数应与请求数一致。

### 常见坑

- 忘记关闭响应体导致连接泄漏。
- 没有错误分支日志，问题难复现。

## 15. 初学者常见问题

### 1. 为什么程序卡住了

通常是 channel 发送/接收不匹配，或所有 goroutine 都在等待。

常见原因：

- 往无缓冲 channel 发送，但没人接收
- `range ch` 时忘了 `close(ch)`
- `WaitGroup` 的 `Add` 和 `Done` 数量不一致

### 2. 为什么 goroutine 没执行完

通常是 `main` 提前退出，需要显式等待。

### 3. channel 什么时候关闭

经验规则：

- 由发送方关闭
- 如果只是一次性通知，不一定需要关闭
- 如果接收方要 `range` 读完，通常需要关闭

## 16. 学习建议

建议按这个顺序练习：

1. 用 goroutine 启动一个异步任务
2. 用 channel 接收结果
3. 用 `select` 加超时
4. 用 `WaitGroup` 等待多个任务
5. 写一个 worker pool
6. 并发请求多个 HTTP 地址并汇总结果

## 17. 总结

Go 并发不只是“多线程语法”，而是一套比较统一的协作模型：

- 用 goroutine 表达并发执行
- 用 channel 传递结果和同步事件
- 用 `select` 同时等待多个事件
- 用 `WaitGroup` 等待一批任务完成

掌握这些模式后，就能稳定搭建异步网络通信、任务调度和消息消费等并发程序。
